# chatluna-plugin-sticker-helper

自动收集会话中的表情包，按人设识别、内化，并让模型用 `<sticker title="…"/>` 发送表情。

## 工作方式

1. **收集**：监听平台原始消息（包括没有唤醒 bot 的群消息），取顶层的 `img`/`mface`/`sticker` 元素（不进入引用）。没有绑定预设的会话不收集。
   - 收集范围在 ChatLuna 规则页「插件 → 表情包」中设置（`sticker.collect`），可按 bot、群、平台分别配置：`sticker` 只收平台标记为表情的图片（`mface`、`sticker`，或 `subType` 为 `1`/`sticker`），`all` 收所有图片，`off` 不收集；默认 `sticker`。
   - 同一个人在同一会话 60 秒内发同一张图只计一次，因此同一群里的多个 bot 看到同一条消息时也只计一次；本实例任何 bot 发出的图都不收集。
   - `autoCollect` 关闭时完全不自动收集，规则页也不显示「表情包」设置。
2. **计数**：每个预设分开统计。同一张图（按内容 SHA-256 判定）在该预设的会话中出现次数达到 `threshold` 后进入待处理队列；上传或复制进来的图直接进入待处理。
3. **跑批**：静态表情按 `gridSize` 张拼成带编号的网格；多帧 GIF 单独跑批，默认每批 1 张、均匀抽 6 帧（含首尾），按 `gifFrames` 排成 2×2、2×3 或 2×4（时间顺序先上排从左到右，再下排从左到右），编号在左上角。`gifPerGrid` 大于 1 时每张动图占一块，各块上下排列、之间留宽间隔。不足所需帧数时按顺序填入、其余留白；动图多或帧多时每格缩小，整张图的宽和高都不超过 `gifSheetSize`。交给 `model` 一次识别，为每张表情生成标题（≤8 字，同预设内重名时自动加 `-1`、`-2`）、描述、适用场景，并按该预设的人设文本判断是否贴合。
   - 某预设的静态或动图待处理分别凑满一批时立即跑（只跑满批）；
   - 每隔 `interval` 分钟跑一次，处理所有待处理（最后一格可以不满）；
   - WebUI 的「立即跑批」等同定时跑批。
   - 一格识别失败（模型报错、输出不合格式、漏了编号）时，相关表情退回待处理，第 3 次失败后标为「失败」。图片无法解码的直接标为失败。
4. **内化**：贴合的表情进入该预设的表情库。
   - `mode: inject`：在 system prompt 中列出全部标题；
   - `mode: search`：system prompt 只给出数量，模型用 `sticker_search` 按想表达的内容找标题。
   - 两种模式都提供 `sticker_detail`，可读取描述，`look: true` 时还会把图片交给模型。
5. **发送**：模型在 `<message>` 里写 `<sticker title="…"/>`，插件按标题在当前预设的表情库中找到图片并发送。找不到时不发送，并记录 warn 日志。
6. **主动收藏**：模型可以调用 `sticker_save`，把会话里的某张图片（按 `<img ref="…"/>` 的 ref）直接加入当前预设的表情库，并自己给出标题、描述和适用场景。收藏的表情直接标为贴合，不经过计数和跑批；标题同样会被规范化（≤8 字）并在重名时加 `-1`，实际标题会返回给模型。已在库中的图片再次收藏时会更新标题和描述。跑批进行中被模型收藏的表情，以模型给的内容为准。
7. **自行管理**：模型可以用 `sticker_edit` 按标题修改表情的标题、描述或适用场景（新标题同样规范化为 ≤8 字，与库中其他表情重名时报错）；用 `sticker_delete` 把一个或多个表情移出表情库，可附带原因。移出的表情标为「不贴合」，原因写入「理由」字段，不会被删除，之后再出现也不会重新进入队列；主人可在 WebUI 改回贴合，模型也可以再次 `sticker_save` 收藏回来。这些工具和其他表情工具一样无需授权。

预设之间完全隔离：计数、标题、贴合结论都只属于一个预设。图片文件按内容共享，存放在 `data/chatluna/sticker-helper/`。

> system prompt 按 epoch 冻结，新内化的表情要到下一个 epoch（新会话、压缩或切换预设）才会出现在注入里。

GIF 原文件保留动画，缩略图仍使用第一帧。旧图片的帧数在启动时自动补齐；已有识别结果保持原样，可在 WebUI 选中后「重新处理」并「立即跑批」，使用多帧重新识别。

## 配置

| 键 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `autoCollect` | 布尔 | `true` | 自动收集总开关；关闭后不再从会话中收集图片，规则中的「收集范围」也不再显示和生效；上传、复制和模型主动收藏不受影响 |
| `threshold` | 正整数 | `2` | 同一张图在某预设的会话中出现多少次后进入待处理 |
| `gridSize` | `9 \| 4` | `9` | 静态表情每批数量（3×3 或 2×2） |
| `gifPerGrid` | 1–4 | `1` | 每批动图数量；多张时每张一块，上下排列 |
| `gifFrames` | `4 \| 6 \| 8` | `6` | 每张动图抽帧数（含首尾帧），排成 2×2、2×3 或 2×4 |
| `gifSheetSize` | px，1024–4096 | `2048` | 动图网格图的最大边长；动图多或帧多时每格缩小，每格最大 384px |
| `interval` | 分钟，≥10 | `360` | 定时跑批间隔 |
| `model` | 模型地址 | `@medium` | 识别用的模型，须支持图片输入；可换成 `@vision` 等 |
| `mode` | `'inject' \| 'search'` | `'inject'` | 表情库交给模型的方式 |
| `maxFileSize` | MiB | `5` | 单张图片大小上限；像素数超过 4096×4096 的图也会被跳过 |

## WebUI

「能力 → 表情包」页面（需要启用 ChatLuna WebUI）：

- 按预设浏览，按状态筛选，搜索标题或描述；
- 上传图片到当前预设（直接进入待处理）；
- 编辑标题、描述、适用场景和贴合结论（手动标题不截断，但同预设内不能重名）；
- 选中后复制到其他预设（只把图片放进目标预设的待处理，不带标题和结论）、重新处理、删除、下载；
- 下载为 zip，内含以标题命名的原图和 `stickers.json`（单次最多 100 MiB）；
- 立即跑批。

写操作需要 4 级权限。

## 存储与清理

- 收集中（未达阈值）的表情 30 天没有再出现会被清理；
- 已处理（贴合、不贴合、失败）的表情不会自动清理，需要在 WebUI 手动删除；
- 没有任何预设引用的图片文件随之删除。

## 已知限制

- 发出的表情是普通图片：OneBot（NapCat）下不会显示为「表情」气泡。
- 识别结果取决于模型对网格图的理解；模型不支持图片输入时跑批会失败并退回待处理。
